## 3. Root Cause Analysis: Why Data Was Previously Misunderstood

An earlier inspection hypothesis suggested that neural data files were missing. A deep audit revealed three root causes for this misinterpretation:

1. **Terminal Sandbox Isolation:**
   - The default development agent terminal runs inside a secure sandbox (`BypassSandbox: false`). While workspace reads are permitted, certain subprocess inspection tools or background task spawns failed to resolve files when shell environments or path lookups interacted with operating system sandbox boundaries. Running unsandboxed (`BypassSandbox: true`) verified that all files were physically intact on the local disk.
2. **Git Tracking vs. Disk Presence (`.gitignore` Rules):**
   - The project's [`.gitignore`](file:///d:/hciproj/NEURO_GRAPE/.gitignore) explicitly excludes `data/processed/`, `data/raw/`, `NeuroGRAPE_handover/processed/`, and `*.tar.gz`. Consequently, Git commands such as `git status` or `git ls-files` report zero tracked files under `data/processed/`, leading observers to falsely conclude the repository lacked data. In reality, the files are preserved locally and also archived in [`NeuroGRAPE_pilot_processed_handoff.tar.gz`](file:///d:/hciproj/NEURO_GRAPE/NeuroGRAPE_pilot_processed_handoff.tar.gz).
3. **Dual Representation Lineage for fMRI:**
   - Unlike EEG and MEG, fMRI preprocessing yields two distinct representations:
     - `raw_window_path`: Points to candidate 4D time series `(96, 96, 60, 4)` in `data/processed/fmri/`.
     - `data_path`: Points to 3D trial-wise LS-S beta maps `(96, 96, 60)` in `data/processed/fmri_beta/`.
   - Observers checking only `data/processed/fmri/` for `data_path` files assumed paths were broken because the files were located in `data/processed/fmri_beta/`. The inventory schema accurately differentiates the two.

## 10. Technical Boundary: Fixed Embeddings vs. Genuine Model Training

Member 3 emphasizes the scientific distinction between two operational modes:

| Operational Mode | Description | Status in Phase 2.5 |
| :--- | :--- | :---: |
| **1. Fixed-Embedding Simulation** | Exponentiated gradient ascent updates distribution weights $q_k$ over static latent vectors generated by a frozen encoder. | **Fully Functional & Tested** |
| **2. Genuine GroupDRO Training** | Full backward gradient propagation through encoder parameters using per-sample contrastive losses weighted by $q_k$. | **Supported via API, Reserved for Phase 3** |

`src/models/training.py` provides the necessary `sample_weights` parameter in `train_epoch` to support genuine parameter updates. In accordance with Phase 2.5 constraints, expensive multi-epoch model re-training was deliberately avoided during this validation phase.
